Gesture Keyboard V2.

01 / The challenge

Start with the user, not the sensor.

A wearable interface only matters if it makes an actual task easier or more reliable than conventional input methods.

The revised design will be chosen by comparing plausible use cases, user workflows, constraints and technical alternatives.

Questions being investigated

  • Who needs a hands-busy input option?
  • What gesture vocabulary is appropriate?
  • What accuracy, latency and false activation rates are acceptable?
  • How can comfort and calibration be quantified?
02 / Stage-gated development

Engineering roadmap

  1. Requirements
    Use-case ranking and measurable acceptance criteria.
  2. Architecture
    Evaluate sensors and system-level design options.
  3. Implementation
    Firmware, electronics, interface and mechanical integration.
  4. Validation
    Bench tests, robustness trials and documented iteration.

Current status: Stage 1. Neither the V2 architecture nor tested performance has been established.

03 / Evidence targets

What needs proving?

Input reliability

Recognition accuracy and false activations measured across defined tasks and usage conditions.

Response time

End-to-end timing through the complete sensor-processing-host input chain.

Wearability

Setup time, user comfort and repeatability across realistic sessions and participants.

Cost and power

Tracked BOM, duty-cycle power measurement and practical battery runtime.
